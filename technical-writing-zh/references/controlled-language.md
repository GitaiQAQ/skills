# 受控词汇与简明语言

处理技术文档时必须读取本文件。本规则借用 ISO 24495-1:2023 的简明语言原则和 ASD-STE100 Issue 9 的受控词汇纪律，并针对中文技术写作调整。它不是标准认证规则，也不照搬英文受控词表或词数限制。

## 判断目标

按 ISO 24495-1 检查四件事：

- **相关：** 内容是否服务目标读者当前的判断或操作。
- **易找：** 读者能否通过标题、顺序和导航快速定位信息。
- **易懂：** 词义是否具体、稳定，句子是否能一次读懂。
- **能用：** 读者看完是否知道下一步动作或判断标准。

删除内容前检查“相关”，调整结构时检查“易找”，改写词句时检查“易懂”，交付前检查“能用”。

## 术语来源

同一概念有多个名称时，按以下顺序选择：

1. 外部协议、平台或标准的原始名称；
2. 代码、Schema、命令和配置中的正式名称；
3. 项目术语表规定的名称；
4. 文档为解释而引入的普通说法。

高优先级名称不得被低优先级别名替换。不要为了“更友好”而翻译代码字段，也不要在中间层创造无法反查实现的简称。

需要普通解释时，首次写成：

> Assertion Result（判断结果）保存每个测点是否超过阈值。

后文继续使用正式名称，不在“Assertion Result、断言结果、判断记录、判定对象”之间轮换。

## 一词一义

- 同一个词在全文只表示一个概念。
- 同一个概念在全文使用同一个名称。
- 一个动作固定使用一个动词。
- 两个行为不同就使用不同词，不为了统一而抹平差异。

例如，“检查”可以表示读取并判断输入；“验证”可以专指执行测试取得证据。先确定两者是否真的不同，再决定统一或保留。

不要机械禁止同义词。受控词汇的目的不是减少词数，而是避免读者误以为换词代表新概念。

## 缩写

- 缩写首次出现时写完整名称和缩写，例如 Chrome DevTools Protocol（CDP）。
- 外部产品只提供缩写作为正式名称时，直接使用正式名称。
- 标题中的缩写必须已在标题前解释；否则写完整名称。
- 不为只出现一次的名称创建缩写。
- 不同时维护中文简称、英文简称和项目别名。
- 大小写、连字符和复数形式保持与来源一致。

代码标识中的缩写不得展开或改写。

## 动词

优先使用能观察到结果的动作：

| 避免 | 改为 |
| --- | --- |
| 进行配置调整 | 修改配置 |
| 提供查询能力 | 查询数据 |
| 完成结果落盘 | 写入结果文件 |
| 实现平台打通 | 调用平台接口 |
| 执行数据封存 | 保存后禁止修改 |
| 做好异常兜底 | 返回明确错误 |

“负责、支持、提供、承载、赋能、打通、收敛”后面必须跟具体对象和动作。无法补出动作时，删除该表达。

不要把有区别的动作都改成“处理”。读取、检查、计算、保存、发布和删除应分别命名。

## 模态词

模态词属于契约，不是语气装饰：

| 词 | 含义 |
| --- | --- |
| 必须 | 不满足就违反要求 |
| 禁止 / 不得 | 明确不允许 |
| 应 | 正常情况下需要满足，例外必须说明 |
| 可以 | 允许，但不要求发生 |
| 可能 | 结果不确定 |
| 建议 | 推荐做法，不是强制要求 |

改写时不得把“必须”弱化为“建议”，不得把“可以”写成系统一定会执行，也不得删除“可能”等不确定性。

只有确实存在例外时使用“通常、一般、原则上”。同时说明例外条件，不能用这些词掩盖未知行为。

## 专业词和项目内部说法

保留专业词需要满足至少一个条件：

- 对应稳定接口、数据对象或行业概念；
- 普通词无法区分两个技术含义；
- 读者需要用该词搜索代码、日志或资料；
- 替换会损失契约精度。

项目内部说法需要通过四项检查：

1. 新读者能否从字面理解？
2. 能否改成明确的主语、动作和对象？
3. 换成普通词后是否损失技术含义？
4. 全文是否始终用它表示同一件事？

不要建立绝对禁词表。“投影”在数据库语境中可能是必要术语，在“运营投影能力”中通常只是包装词。

## 名词和指代

- 连续名词难以判断关系时，用“的”、介词或动词展开。
- 用具体对象替代“相关内容、有关能力、该机制、这一块”等空指代。
- 代词跨段、存在多个候选对象或涉及安全条件时，重复完整名称。
- 为避免歧义而重复术语不是文风问题。
- 不把动词全部名词化。优先写“系统检查报告”，不写“系统执行报告检查操作”。

## 句子和指令

- 使用主动语态并指出执行者。
- 指令直接写动作，例如“运行测试”，不写“测试应该被运行”。
- 一句承载一个主要判断；条件和对应结果可以留在同一句。
- 警告先写禁止事项或触发条件，再解释原因。
- 不为缩短句子删除主语、对象、范围或例外。
- 句子长度只用于发现问题，不作为中文硬门槛。

## 建立文档词汇表

长文档或多人维护的文档需要先建立最小词汇表。只记录跨章节、容易混淆的词：

| 名称 | 定义 | 来源 | 禁止别名 |
| --- | --- | --- | --- |
| 正式名称 | 一句话定义 | Schema、代码或标准 | 会造成歧义的旧称 |

局部变量、只出现一次的概念和正文已经解释清楚的普通词不进入词汇表。

修改术语时搜索全文、图表、代码片段、配置示例和交叉引用。只替换正文会造成第二套名称。

## 完成检查

- 正式名称是否来自可验证来源；
- 缩写是否首次展开且字面一致；
- 同一概念是否出现多个名称；
- 同一个词是否承担多个含义；
- 动词是否能对应可观察动作；
- 模态词和不确定性是否保持原义；
- 抽象词是否有具体对象、输入和结果；
- 指代是否存在多个可能对象；
- 读者是否能找到信息并据此行动。
