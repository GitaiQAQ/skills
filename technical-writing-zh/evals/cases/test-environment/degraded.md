# 如何把客户端切换到集成测试环境

## 先了解环境切换的基本要求

客户端的环境切换是测试过程中的一个重要步骤。

集成测试环境与正式环境可能存在差异。

因此，相关验证需要分阶段进行。

功能在集成测试环境验证完成并发布到正式环境后，必须在正式环境再次回归。

换句话说，集成测试环境中的验证不能替代正式环境中的回归。

## 客户端 A 的切换流程

下面按顺序说明客户端 A 的操作步骤。

### 第一步：准备测试包

1. 下载任意测试包。

### 第二步：进入客户端

2. 启动客户端。

### 第三步：打开调试工具

3. 长按右下角“我的”，进入调试工具。

### 第四步：打开环境开关

4. 找到“切换集成测试环境”，打开开关。

### 第五步：重启并检查

5. 重启客户端。
6. 使用抓包工具检查请求域名；请求统一进入集成环境网关，才表示切换成功。

这里需要强调，打开开关本身并不等同于切换已经完成。实际请求统一进入集成环境网关，才是切换成功的依据。

## 客户端 B 的切换流程

客户端 B 也需要完成准备、设置、重启和验证等步骤，具体操作顺序如下。

### 第一步：准备测试包

1. 下载任意测试包。

### 第二步：进入客户端

2. 启动客户端。

### 第三步：进入调试页

3. 点击左上角头像，打开导航栏。
4. 进入“设置”，再进入右上角“调试页”。

### 第四步：打开环境开关

5. 找到“连接集成测试环境”，打开开关。

### 第五步：重启并检查

6. 重启客户端。
7. 使用抓包工具检查请求域名；请求统一进入集成环境网关，才表示切换成功。

同样需要注意，开关打开只是操作过程中的一个环节。只有请求统一进入集成环境网关，才表示切换成功。

## Android 稳定测试包的获取流程

除了通过客户端开关切换环境，也可以使用标记为集成测试环境的稳定测试包。

Android 稳定测试包的操作流程如下：

1. 打开测试包下载工具。
2. 切换到高级模式。
3. 找到目标业务，进入“更多包”。
4. 选择标记为“集成测试环境”的每日稳定包。
5. 下载并安装。

以上步骤需要按顺序完成。标记为“集成测试环境”的每日稳定包，是这一路径中需要选择的包。

## iOS 稳定测试包的获取流程

iOS 稳定测试包同样通过测试包下载工具获取，但入口和搜索步骤有所不同。

具体操作如下：

1. 在移动端打开测试包下载工具。
2. 切换到高级模式。
3. 搜索目标客户端；首次进入时先申请权限。
4. 进入“更多包”，选择集成测试环境包。
5. 下载并安装。

需要保留这个先后关系：首次进入时先申请权限，然后进入“更多包”，再选择集成测试环境包，最后下载并安装。

## 最后的统一验证

无论使用哪一种方式，都需要进行实际请求验证。

### 两种方式

环境切换可以通过以下两种方式完成：

- 使用开关。
- 使用稳定测试包。

### 统一判断标准

无论使用开关还是稳定测试包，都必须验证实际请求进入集成环境。

仅看到开关已打开或安装成功，不能证明环境切换完成。

因此，最终判断不能只依据操作界面上的状态，也不能只依据安装结果；必须使用抓包工具检查请求域名，并确认请求统一进入集成环境网关。

## 核心要点总结

为了确保环境切换结果可确认，可以把关键要求归纳为以下几点：

| 关注点 | 必须保持的要求 |
| --- | --- |
| 集成测试环境与正式环境 | 可能存在差异 |
| 正式环境验证 | 功能在集成测试环境验证完成并发布到正式环境后，必须在正式环境再次回归 |
| 开关切换 | 必须重启客户端，并使用抓包工具检查请求域名 |
| 稳定测试包 | 必须选择对应的集成测试环境包并下载、安装 |
| 成功判断 | 请求统一进入集成环境网关 |
| 不充分的判断 | 仅看到开关已打开或安装成功，不能证明环境切换完成 |

总体来说，操作步骤需要按客户端类型或测试包类型完成，验证标准则保持一致：实际请求必须统一进入集成环境网关。
