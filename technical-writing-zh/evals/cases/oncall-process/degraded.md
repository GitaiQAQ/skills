# 线上问题处理规范

这份规范用于对线上问题的处理过程进行统一说明。

## 问题处理流程

### 先进行问题承接

用户反馈问题后，首先需要搜索已有知识。

这是问题处理的起始动作，也是后续是否转人工的重要依据。

如果已有答案，可以直接回复用户。

如果没有答案，则转人工，并填写问题表单。

### 进行受理和排查

值班人员负责受理问题。

同时，值班人员负责进行初步排查。

当问题需要研发介入时，应转交研发处理。

也就是说，问题需要研发支持时，由研发继续承接和处理，而不是停留在初步排查阶段。

### 确认问题结果

问题修复后，必须由用户确认结果。

用户确认结果是问题处理完成的重要环节。

## 关单条件

关单需要满足明确条件。

只有以下两种情况可以关单：

1. 反馈的问题已经解决。

   这种情况下，关单时建议同时关闭对应沟通群。

2. 问题短期内无法定位原因且无法复现。

   这种情况下可以关单，但应保留沟通群。

问题尚未解决时，不得自行关单。

换句话说，问题没有解决，就不能因为处理流程已经进行过而自行关单。

## 复盘和事故定级

事故定级需要关注用户体验定级与研发定级之间的差异。

如果用户体验定级与研发定级的差值大于或等于 1，应重新讨论并纠正事故定级。

### 不同级别事故的复盘要求

- P0、P1 事故需要单独召开复盘会议并发布事故通报。

  需要在 24 小时内组织复盘。

  需要在 3 天内发布复盘报告。

- P2 及以下需要复盘的事故，应在 3 个工作日内组织复盘。

  并且，应在 7 个工作日内发布复盘报告。

### 复盘材料准备

复盘文档应至少提前 3 小时发给参会者阅读、评论和补充。

提前发送复盘文档，是为了让参会者能够进行阅读、评论和补充。

## 高优问题上报

高优问题需要及时上报。

及时上报可以使值班人员尽快了解影响，并协调资源定位和处理问题。

这意味着，高优问题的上报需要同时承载影响同步、资源协调以及问题定位和处理的要求。

### 体验级别达到 P2 及以上时

当体验级别达到 P2 及以上时，一级值班人负责全程跟进。

一级值班人还负责推动解决，并纠正定级。

如果需要更高层级作出业务判断，应按既定值班层级逐级升级。

逐级升级时，不得跳过当前负责人后无人继续跟进。

也就是说，即使问题需要向更高层级升级，当前负责人仍需要有后续跟进，不应出现无人继续跟进的情况。

### 上报信息

上报信息至少应包含以下内容：

- 问题现象和影响范围；
- 当前定级及其依据；
- 已完成的排查；
- 当前负责人；
- 需要协调的资源或待决策事项。

这些信息共同支撑问题上报，使问题现象、影响、定级、排查、负责人以及资源或决策需求能够被同步了解。

### 安全类问题

安全类问题由安全值班人员统一跟进。

业务值班人员协助。

如果无法确定问题性质，应交由当班安全负责人确认。

不得由非责任人自行下结论。

因此，在问题性质不明确时，需要先由当班安全负责人完成确认，不能由非责任人自行判断结论。
