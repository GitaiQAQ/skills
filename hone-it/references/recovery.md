# Recovery

## 触发条件

- `unlazy` 的恢复 gate 被触发。
- 项目原生健康检查失败，或已采用候选的 evaluator/CI 证据被证明无效。
- 项目原生监控、发布或 Code Review 流程要求恢复。

## 恢复流程

1. 让 `unlazy` 停止新的维护循环，并保持触发 recovery 的 gate 为阻断状态。
2. 在项目原生审计或事件系统中保存故障版本、时间线和 evaluator/CI 证据；不要用 Note 代替。
3. 从项目原生来源解析不可变 LKG，并验证制品可获取。
4. 使用项目已有回滚、回退发布或恢复命令；本 Skill 不发明命令。
5. 在隔离环境先验证恢复路径；涉及多环境或多阶段组合时调用 `prove-it`。
6. 执行项目原生健康检查，并通过项目原生 Code Review/审批入口确认结果。
7. 将故障候选保留在 archive 并标记不可晋级，不删除现场。
8. 只有原生恢复 gates 全部通过后，才让 `unlazy` 解除阻断并安排下一项。

## LKG 规则

- LKG 必须是不可变提交或制品标识，不能只是可移动分支名。
- LKG 的存储、推进、回滚和审批方式由项目原生机制定义。
- 失败、未知或尚未通过项目健康检查的候选不得替代 LKG。

## 恢复报告

报告触发原因、archive 中的故障候选、恢复到的 LKG、实际调用的原生命令和 gates、Code Review 状态及残余阻断。若无法恢复，保持 `unlazy` 阻断，不把“计划恢复”写成“已恢复”。
