# Behavior 条目字段

本文件是字段与状态的唯一维护位置。使用 [模板](../templates/behavior.yaml) 时替换占位内容，不复制业务默认值。字段只有在具备当前用途时才填写；未知与不适用必须分开。

## 必填身份与行为

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定标识，使用 `域.对象.动作` 的小写英文形式；语义修改保留 ID |
| `owner` | 用户或项目授权记录中的人或角色；未知写 `TODO`，不得由 AI 自赋 |
| `status` | 仅 `hypothesis / pending_decision / active / deprecated / conflict` |
| `introduced_in` | 项目定义的行为版本；尚未确定时写 `TODO`，不是任意填写的发布版本 |
| `actor` | 触发者 |
| `intent` | 一句话业务目标 |
| `given` | 前置状态与依赖 |
| `when` | 触发动作 |
| `then` | 可观察、可由 Oracle 判断的结果 |
| `rationale` | 引入或修改原因，以及可定位的需求、代码、事故或反馈来源 |

`hypothesis` 用于尚未确认的候选；缺少决策或晋级条件时使用 `pending_decision`；语义冲突使用 `conflict`，不得被普通待决策状态掩盖。晋级条件见 [SKILL.md](../SKILL.md)。

## 必填追踪与证据

- `implementation`：实际代码、配置或 Adapter 路径；尚无实现写 `TODO`。
- `driver`：现有测试命令或执行方式，包含必要执行目录；尚未准备写 `TODO`。
- `oracle`：实际断言位置与判断规则；命令退出码不能代替业务断言。
- `evidence`：最近实际运行的引用。未运行也要明确记录，不能留成看似成功的值。
- `review_log`：Owner 确认、裁决和回退记录；未审查为 `[]`，晋级前必须能追溯确认人、版本与结论。

`evidence` 使用以下最小结构：

```yaml
evidence:
  result: not_run
  run_id: TODO
  minimal_failure: null
```

`result` 允许 `not_run / passed / failed / blocked`。它是运行结果，不是行为生命周期状态。`run_id` 指向实际 CI 运行或已保存的本地记录；没有记录时保持 `TODO`，不能报 `passed`。失败反例存在时填写 `minimal_failure`，没有时使用 `null`。

已有项目使用其他证据结构时保留其约定，通过映射表达相同信息，不批量改写历史记录或建立第二套证据。

运行记录保存行为版本、实现版本、验证版本、必要输入、命令、环境和输出位置。它可以引用项目现有报告，不必把全部元数据复制到条目中。历史运行记录保留，条目更新最近引用不能覆盖旧证据。

## 按需字段

| 字段 | 何时填写 |
| --- | --- |
| `changed_in` | 修订已有行为时记录新行为版本 |
| `deprecated_in` | 废弃时记录退出版本与理由 |
| `error` | 有明确错误码、错误字段或失败传播要求 |
| `side_effect` | 有外部请求、消息、写入或禁止发生的副作用 |
| `invariants` | 已确认对一类输入成立的性质；写明适用状态，不把拒绝无效输入写成所有输入都有效 |
| `quality_bar` | 已确认的性能、安全、兼容或成本要求；数值必须有单位、比较方式和来源 |
| `hidden_scenarios_ref` | 独立验证的受控引用；晋级前必须具备，准备阶段可为 `TODO` |
| `conflicts_with` | `conflict` 时列出冲突 Behavior ID，同时在理由中保存双方来源 |

不适用的可选字段可以省略；适用但未知时写 `TODO` 并保留待决策状态。`[]` 表示已确定没有条目，不能表示尚未调查。

## 版本与派生

行为版本、实现版本、验证版本与发布版本必须区分。复用项目已有版本管理，不预设额外字段或提交方式。生效语义修改必须能恢复旧版本；差异说明包含新增、修改、废弃，且不能把待决策条目描述为已发布功能。
