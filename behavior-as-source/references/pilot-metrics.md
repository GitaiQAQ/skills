# 试点指标与晋级门槛

Behavior as Source 是待验证的工程假设。试点必须允许得到“不成立”的结论。

## 衡量维度

### 实体与同步成本

- 长期维护的独立事实源数量；
- 同一规则在不同材料中的重复与不一致数量；
- 文档维护和人工同步时间。

### 行为质量

- 真实问题转成回归行为的比例；
- P0 / P1 行为遗漏数；
- 隐藏场景退化数；
- `pending_decision` 平均停留时间；
- 错误 Oracle 和重复行为数量。

### 交付效率

- 从想法到第一个可执行场景的时间；
- 从行为确认到代码通过的时间；
- 人工开发与测试分钟数；
- 返工轮次、Token、工具调用和墙钟时间。

### 演化能力

- Behavior Diff 生成的 Release Notes 是否可用；
- 第二个模块能否复用相同 Registry / Driver / Oracle 协议；
- 历史行为能否被准确查询和回放。

## 扩大试点的晋级门槛

试点开始前确定观察窗口、数据来源和各项判定标准。没有基线时先记录，不补造统一阈值。首个模块满足下列条件中除第 5 项外的要求后，可以在第二个模块验证复用；第 5 项也满足后，才支持更广推广：

1. 独立事实源与同步成本明显下降；
2. P0 / P1 行为遗漏没有上升；
3. 开发和测试人力真正前移到行为决策，而不是转化为维护 Gherkin 的新成本；
4. 自动生成的产品说明和 Release Notes 可直接使用或仅需少量编辑；
5. 第二个模块可复用协议，不是为第一个案例定制；
6. Registry 维护成本没有随场景数失控；
7. 错误行为可被快速定位、回滚和审计。

## 停止扩张的信号

- 场景膨胀，Owner 无法持续确认；
- AI 生成大量低质量行为，筛查成本高于原流程；
- 团队在 Registry 之外重新维护 PRD 和测试。
