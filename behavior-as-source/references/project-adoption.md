# 在现有项目中启动最小试点

本指引只用于首次接入，或已有行为文件但没有可执行链路的项目。目标是完成一个小范围“来源 → 条目 → 实现与验证映射 → 真实证据”的试点，不要求首次接入就晋级为 `active`。

## 1. 读取项目现状

定位目标项目根目录并阅读项目指令。针对用户指定模块，直接读取相关实现、测试、需求和现有决策记录；不要扫描整个项目来建立完整行为库。

确认以下事实，优先从仓库读取，不逐项询问用户：

- 模块边界、用户本次目标及可观察结果；
- 是否已有 Registry、稳定 ID、版本和 Owner 约定；
- 测试入口、依赖环境、现有断言和输出保存位置；
- 当前规则的来源，以及代码与需求是否冲突。

用户没有指定模块时，选择一个输入输出清晰、有现有测试、依赖较少的模块，并说明选择理由。无法判断时只询问试点范围，同时继续读取项目通用指令。

## 2. 复用已有位置，否则使用最小目录

已有 Registry 时直接复用，不建立并行副本。没有约定时，默认创建：

```text
docs/behavior/
  adoption.md                 本模块的范围、约定、验证入口与试点基线
  <domain.object.action>.yaml  当前任务所需的行为条目
```

`adoption.md` 是接入约定，不复制行为断言。运行结果沿用项目已有存储；确无存储时，实际运行后才创建 `docs/behavior/evidence/<run-ref>.md`，保存必要记录和输出摘要。不要预建空目录或复制本技能的背景论证。

接入记录至少说明下列内容，按实际项目填写，不保留无用章节：

```markdown
# Behavior as Source 试点

## 范围
目标、非目标、保持不变的代码结构和流程。

## 来源与责任
来源文档与实现位置；已确认 Owner 或 TODO；待决问题。

## 项目约定
Registry 路径；稳定 ID 规则；行为版本的项目定义与历史保存方式。

## 验证入口
现有测试命令、执行目录、所需环境；实现和测试路径；证据保存位置。
独立验证由谁维护、在哪里执行；尚不具备时明确记录。

## 试点验收
当前试点范围内的完成条件、观察窗口、比较基线与停止信号。
已测数据与未测数据分开；无数据时不估造收益。
```

不自动修改项目级 `AGENTS.md`、CI 或测试配置。接入路径在交付说明中给出即可；用户要求项目规范集成时再更新相应入口。

## 3. 完成首条可追溯行为

优先从当前需求或已有测试支持的真实行为开始。读取 [behavior-schema.md](behavior-schema.md)，使用 [behavior.yaml](../templates/behavior.yaml)，替换占位内容。

- 只记录当前模块必要规则；一个输入例子不是全部行为空间。
- Owner 无法确认时保留 `TODO` 和 `pending_decision`，不阻止条目与映射准备。
- 有效实现路径、测试命令和断言可以直接作为 implementation、Driver 与 Oracle；不要新建包装层。
- 先运行现有测试。新测试仅用于既有测试漏掉的本次需求，并遵守项目规则。
- 没有可运行环境时记录准确阻塞条件，不为完成接入而模拟成功。
- 首次落地不要求生成用户手册或版本说明；没有消费者就不创建。

## 4. 保存真实证据

证据中能找到行为版本、实现版本、验证版本、输入或 Fixture、命令、执行目录、必要环境、结果和输出位置。使用实际项目版本标识；工作区未提交变更时，关联运行时保存的相关 diff 或内容摘要，不能只用 HEAD 代表被测内容。

没有 CI Run ID 时，以实际存在的本地记录路径作为 `run_id`。记录失败同样有价值；命令退出成功还需要确认断言确实执行。输出文件不存在、仅列出计划命令或检查了 YAML 格式，都不算行为运行证据。

## 5. 首次接入的完成标准

- 接入记录明确试点范围、Owner 或待决问题，以及现有验证入口；
- 当前任务需要的行为条目能追溯到来源与真实实现；
- 现有测试已执行并保存证据，或明确列出未执行原因和下一步；
- 状态符合现有证据，没有把准备完成写成行为已生效；
- 没有第二套 Registry、额外框架或无消费者的派生文档。

在此停止首次接入。只有用户继续要求实现或扩大试点时，才处理后续范围。需要评估推广时，再读取 [pilot-metrics.md](pilot-metrics.md)。

## 常用请求

- “用 $behavior-as-source 在当前项目的登录模块启动最小试点，复用现有测试，不建平台。”
- “用 $behavior-as-source 把这次需求落成行为条目，先找已有行为，再完成本次实现与验证。”
- “用 $behavior-as-source 对齐这次事故涉及的行为，保留反例和真实运行证据。”
